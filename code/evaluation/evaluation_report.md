## 1. Approach

A deterministic, evidence-first engine (no model decides state or policy):
1. **Loaders** dispatch every evidence file by content signature (SQL, JSON shapes, 7 log dialects, handover text, PDF text, committed screenshot transcriptions) into observations `(file, time, system, resource, state, identifiers, PII fields)` and coverage (which snapshots list every row).
2. **Evidence store** with an `as_of(audit_at)` view: a file captured after the cutoff does not exist for that case (ADR 0002).
3. **Identity**: exact, case-insensitive identifiers including history and the sha256 of every email; look-alikes never match.
4. **Linking**: same record or trace join, search `source_resource_id`, catalog claims checked against their artifact (ADR 0005), and activity account candidates (unique survivor only, ties logged; ADR 0003/0004).
5. **State** = latest observation at or before audit_at across all tables (replicas included); omission is weak evidence (ADR 0014).
6. **Policy** from `deletion_rules.csv` with an ordered category table (tag > file content > activity claim > message text > system default).
7. **Verdict + plan**: INCOMPLETE iff a grounded violation exists; COMPLETE cites evidence for every step; unproven resources become future checks only (ADR 0006). Intent: rules decide clear texts, a pinned cached model the rest (ADR 0008).

## 10. Failures found and improvements made

- L0 gate failed without pandas; broken copies failed for the wrong reason → optional pandas, check ids asserted (T01).
- Scorer gave free field-accuracy credit when nothing aligned → 0 when steps exist but none align (T02 baseline).
- Observability logs containing `lookup_key=` were sniffed as readback logs (14 instead of 11) → strict readback grammar (T04).
- Bundle collections, empty lists and inventory scope are not exhaustive (7 gold contradictions) → ADR 0014, weak coverage (T06).
- Citations used a later covering file instead of the latest file naming the resource → citation rule (T10).
- A March 404 from another lifecycle of a reused id produced an extra step → ADR 0016 stale links (T10).
- Metamorphic M8 target violated its own precondition (not a pipeline bug) → target selection fixed (T15).
- Blind audit: templated message text outranked a DELETE claim → support category precedence fixed (silver audit).
- The literal audit caught case ids in docstrings/comments three times → removed.
- A key set without the `openai` package crashed the run → guarded import, bounded retries, failures never cached (robustness fix).
- `final` was red on a machine without pandas (a test compared the whole warning list) → optional-dependency warnings filtered; `final --matrix` reruns the tests with each optional dependency blocked and found 2 more such tests (T14).
- `explain.py` did not parse on Python 3.11 (backslash in an f-string) → fixed, plus a test that compiles code/ on 3.11 (T14).

## 11. Known limitations and their estimated cost

- **Tied account candidates** (136 eval cases): the account step is omitted rather than guessed; ~1.28 steps each.
- **No account delete in the window** (12 cases, the 42-hour family): no account step.
- **Anonymized analytics reachable only through activity bursts**: ~0.22 missing VERIFY_RECORD_ANONYMIZED per case.
- **Audit records that appear nowhere** (~3/32 samples): unreachable.
- **Unconfirmed catalog claims** (object_19, export_1842, tombstone_17) are not linked; a backup without a restore flag is unproven.
- **Unlabeled rules** (§9) may disagree with the hidden labels.
